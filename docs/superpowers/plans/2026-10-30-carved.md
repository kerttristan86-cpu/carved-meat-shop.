# CARVED implementation plan

**Goal:** Connected local shop operations with auditable stock and balanced bookkeeping.
**Architecture:** Next.js tablet client and authorized API. Persistent PGlite PostgreSQL, Drizzle auth adapter, Better Auth owner sessions. One server process owns the data directory. Monetary and weight calculations use Decimal, rounded half-up to cents and grams. No public deployment.
**Spec:** CODEX-BUILD-PROMPT.md and attached supplemental request.

1. Database and transaction engine: migrations, immutable stock and journals, weighted average cost, products, parties, orders, receipts, sales, payments, returns, expenses and idempotency. Write acceptance tests first and run through fractional weight, partial receipts, concurrency, retries, insufficient stock and balanced reports.
2. Secure access: Better Auth with closed registration, CLI owner bootstrap, authorized mutations and same-origin checks. Test unauthenticated access and real login.
3. Tablet application: POS, inventory and transfers/counts, products/prices, purchases/suppliers, customers/invoices, returns, expenses, reports, configurable documents/settings and audit. Preserve cart locally and use stable retry keys. Use supplied logo, specified colors, 44px controls.
4. Delivery: test backup/restore into a separate directory, business tests, typecheck/build and tablet/receipt visual QA. Document setup, owner provisioning, operating guide and explicit accountant/hardware limitations.

## Assumptions and review focus
- BOX means PHP/kg; boxes tracked separately at receipt/sale, not converted to kg.
- Bulk threshold is 5kg per line; owner override requires a reason.
- Services use configurable units and never deduct stock.
- Accrual bookkeeping, perpetual moving weighted average, no VAT/tax calculation until accountant config/review.
- Purchase receipt recognizes inventory and payable; orders/drafts do not post. Customer invoice posting recognizes revenue and COGS once; payments settle balances only.
- Returns are linked line quantities with cumulative limits, restore original COGS, and refund only already collected cash; unpaid amounts reduce receivables.
- Review risks: concurrent retries, duplicate product cart lines bypassing stock limits, changes to prices/costs, overpayment/overreturn, timezone boundaries.
